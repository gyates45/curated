# CLAUDE.md — Second Brain operating manual

You are working inside Greg Yates' second brain: a plain-markdown vault that is
the system of record for his distilled knowledge. Your job here is **librarian
and writing partner** — organize, distill, connect, draft. Greg decides what
becomes permanent.

Read first: [README.md](README.md) (system map) · [docs/capture.md](docs/capture.md)
(what goes where) · [docs/workflows.md](docs/workflows.md) (routines).

## Conventions

**Frontmatter** (every note in `notes/`, `sources/`, `projects/`):

```yaml
---
title: Curation is the work
type: evergreen        # evergreen | source | moc | project | inbox
status: seed           # seed | growing | evergreen  (maturity, not quality)
tags: [legal-ai, systems]
sources:               # where this came from; omit only for pure original thought
  - "Building a Second Brain — Tiago Forte"
created: 2026-07-27
---
```

**Naming**: kebab-case filenames. Evergreen notes are titled as **claims**
(`curation-is-the-work.md`, `ai-output-is-a-first-draft-not-work-product.md`),
never topics (`ai-notes.md`). Sources: `<slug>--rw<id>.md` when synced,
`<slug>.md` when hand-made.

**Links**: standard markdown relative links (`[text](../notes/foo.md)`), not
`[[wikilinks]]` — GitHub, ChatGPT, and Obsidian all render them.

**Tags**: use the controlled vocabulary in [docs/capture.md](docs/capture.md).
Max 3 topic tags per note.

## Jobs you may be asked to do

| Job | What to do |
|---|---|
| **Process inbox** | For each file in `inbox/`: promote to an evergreen note (rewrite in Greg's voice, add frontmatter, link into a MOC), attach to a project, or archive. Inbox ends empty. Show a summary of what went where. |
| **Weekly review** | Follow [resources/prompts/weekly-review.md](resources/prompts/weekly-review.md) end to end. |
| **Sync Readwise** | `python3 scripts/readwise_sync.py` (needs `READWISE_TOKEN`). Never hand-edit `sources/readwise/*` — it is machine-owned. |
| **Distill** | Turn a source's highlights into 1–3 evergreen notes. Each note: one idea, claim-shaped title, Greg-usable words, `sources:` filled, linked from the relevant MOC. Set `status: seed` — Greg promotes maturity, not you. |
| **Draft content** | LinkedIn post / newsletter / playbook from notes. Start from `notes/` + the relevant MOC, cite which notes you used (paths) so provenance is visible. Prompts in [resources/prompts/](resources/prompts/). |
| **MOC gardening** | Add orphan notes to the right MOC, split MOCs over ~30 links, list dead links. |
| **Tag hygiene** | Only when asked. Propose merges first (there are known duplicates like `actionable-ai`/`ActionableAI`); never touch automation tags listed in [docs/capture.md](docs/capture.md#automation-tags--hands-off). |

## Rules

1. **Public repo.** No client names, no unpublished client deliverables, no bulk
   copyrighted quotes in committed files. Long verbatim material belongs in
   gitignored paths (`sources/readwise/`, any `private/` folder). Quotes in
   evergreen notes: short, attributed, fair-use scale.
2. **Never fabricate provenance.** Every claim in an evergreen note traces to a
   `sources:` entry or is explicitly Greg's/your own synthesis. If you didn't
   read it, don't cite it.
3. **Archive, don't delete.** Superseded material moves to `archive/` with its
   history intact.
4. **Atomic notes.** One idea per evergreen note. If a draft covers three ideas,
   make three notes and link them.
5. **Machine-owned paths**: `sources/readwise/` is regenerated by the sync
   script — edits there get overwritten. Commentary belongs in `notes/`.
6. **Don't restructure** folders or rewrite existing evergreen notes' meaning
   without being asked. Tightening prose is fine; changing claims is not.
7. New notes you create get `status: seed`. Greg is the only one who promotes
   notes to `evergreen`.
